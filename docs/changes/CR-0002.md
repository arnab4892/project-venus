# CR-0002 — Allow external API model for extraction of public content

## 1. Why
The schema-constrained extraction step (section classification + typed field
extraction with evidence) is the highest-leverage place to use a stronger model:
better extraction means fewer review edits and higher fact quality before
promotion. Because extraction runs offline over **public** content only — the
website pages and the two catalogue PDFs, which contain no customer or
conversation data — using an external API LLM there does not weaken the privacy
posture that matters: the customer-facing runtime stays self-hosted and no
customer data leaves Nyalazone infrastructure. This change scopes PRD-N-002 to
permit that, while keeping the embedding model self-hosted (runtime query and
chunk vectors must be produced by the same model).

## 2. PRD change
Modify only — no requirement id added or withdrawn. Version bump MINOR: PRD 1.1 → 1.2.

| Requirement | Change | Before | After |
|---|---|---|---|
| PRD-N-002 | Modified | "Self-hosted open-source LLM and embedding model; no customer data leaves Nyalazone infrastructure." | "The customer-facing runtime shall use a self-hosted open-source LLM and embedding model, and no customer data shall leave Nyalazone infrastructure. The offline content-extraction pipeline may use an external API LLM, restricted to public website/catalogue content (which carries no customer data); the embedding model remains self-hosted (runtime query and chunk vectors must share it)." |

What changed: the self-hosted-model constraint is split by stage. The
customer-facing **runtime** keeps the self-hosted LLM + embeddings and the "no
customer data leaves" guarantee, unchanged. The **offline extractor** is
permitted to use an **external API LLM**, bounded to **public content only**. The
**embedding model stays self-hosted** in both stages (extractor-LLM only, not
embeddings). No id added or withdrawn.
