Jyotech Agent Data Model

Iteration 1. Three schemas in one Postgres database: a read-only fact schema rebuilt per content release, a per-release vector table, and an operational schema the runtime writes to. Sample rows are drawn from what the public site and the two catalogue PDFs actually say; a real conversation is then traced through every table.

facts.* — read-only, per release vec.* — embeddings, per release ops.* — runtime writes

Operational schema ops.*

Written at runtime, never rebuilt. turn is one orchestrator pass and the parent of all agent and tool logs; message is every bubble the widget shows, and a turn owns one or more of them in either role — two quick user messages can trigger one pass, and one pass can emit an answer, a follow-up question, a status bubble and a document card as separate messages. The FK therefore lives on message.turn_id, not on the turn.
